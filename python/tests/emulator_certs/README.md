# Emulator certificate chains

Device certificate chains of the emulators, used by `test_authentication.py` to test
the built-in root keys (`trezorlib.authentication.ROOT_PUBLIC_KEYS`). They are issued
by the debug roots.

The files are generated by `core/tools/generate_certificates.py` (`make certs` / `make gen`)
together with the emulator's C headers. Do not edit them manually.

The files are named `<attestation_source>_<MODEL>.der`, where `attestation_source` is
a value of `trezorlib.authentication.AttestationSource`.

- `optiga_<MODEL>.der`: copy of `core/embed/sec/optiga/unix/certs/<MODEL>.der`.
  Device key: P-256 private key `0100…00` (see the README in the same directory).
- `mcu_<MODEL>.der`: copy of `core/embed/sec/secret/unix/certs/<MODEL>.der`.
  Device key: ML-DSA-44 key from seed `0303…03` (see
  `core/embed/sec/secret_keys/unix/secret_keys.c`).
- `tropic_T3W1.der`: chain stored in user data slots 3–5 of
  `tests/tropic_model/base_config.yml`, without the 2-byte length prefix.
  Device key: Ed25519 key in ECC slot 0 of the same file.

The device keys are hardcoded in `test_authentication.py`. Update them there when the
emulator device keys change.
